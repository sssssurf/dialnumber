## 11 月 19 日交互与性能复核

以 0.12.0、提交 `b3eeaaa` 为本轮直接基线。增加 `remove_last_digit`，可逐位删除
并重新分组；读取未修改的输出复用已有结果，clear 和有效输入会正确更新状态。
国家和调用码建立固定索引，保持原表顺序；前缀语法树和格式分组缓存附在元数据
行上，不缓存任意用户输入。32 个捕获转换计划及原版对照继续核查行为。

人工号码解析入口现在在去空白前执行 250 UTF-16 单元上限。旧版接受的更长补空格
输入改为拒绝；原版 Java 134 场景包含 250 单元接受和三项 TOO_LONG 结果。仍分别
测试过长公开 PhoneNumber 的校验与解析器拒绝路径。基准和编辑回归见
[optimization-20261119.md](optimization-20261119.md)。

当前代码 `d6cb10d` 的[公开 CI](https://github.com/sssssurf/dialnumber/actions/runs/44444643561)
已通过全部任务。实际安装结果及源码一致性另记于 published-consumer-results.json。

## 11 月 18 日新增与复现（保留）

本轮以 0.11.0、提交 `813ac7e` 为直接比较基线。十月原提交和此前十一月修复的
记录仍保留。0.12.0 的新增能力与验证如下。

| 实际问题或缺口 | 改进 | 复验入口 |
| --- | --- | --- |
| +800 等网络仅显示连续数字，缺少逐键分组 | 九个非地理网络导入原始格式规则，复用地区格式解释器 | `format_international`、`format_national(pn, "001")`、`AsYouTypeFormatter` |
| `2015550123 x 0042` 被拒绝 | 短分机标记与数字之间允许空格，保留前导零 | 原版 Java 参考中的 spaced extension 场景 |
| +979 八位号码的本地长度可能性缺失 | 当原始规则与已有验证模式相符时补入 localOnly | `is_possible`、`possible_types`；与实际规则有效性分别断言 |
| 非地理格式未进入原版参考断言 | 原版 Java 扩至 130 场景，九网络检查国际和国内显示；JS 对照也加入网络显示 | `gen-google-compat`、`gen-compat` |
| 数据更新可能再次丢掉网络格式 | 提取器保留格式和本地长度，生成器检查网络表校验和 | `import-network-formats`、`update-metadata`、`gen-non-geo --check` |

`+800 12345678 x 0042` 现在解析、显示为 `+800 1234 5678 ext. 0042`，国内网络
显示为 `1234 5678 ext. 0042`。裸网络显示需要已知调用码才能解析，`001` 表示九个
网络而非唯一国家。手工给定 `+800` 后往返保留号码和分机。

## 范围与工程取舍

地区与网络共用格式模式、捕获组分配和替换逻辑，避免每个网络写特殊分组分支。
格式由固定原始 XML 产生。当前旧表里较新的验证模式保留，新增格式和本地长度
另记来源与校验和，防止更新显示规则时降级验证数据。

两套电话参考的元数据年代和部分语义不同，JS 的 15 案例、28 字段差异继续明确
记录，六条原版 Java 逐键轨迹的 13 处中间布局差异也保留。新增网络测试验证数字
守恒和完成后的分组。交互编辑范围、实际号码可达性和上下文权威映射边界见
[known-limitations.md](known-limitations.md)。

本文件用于十一月成果核查。报名提交及组织方审核状态以实际通知为准。
