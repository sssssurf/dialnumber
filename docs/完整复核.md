# dialnumber 完整复核与改进（2026-11-09，0.10.0）

正式验收未通过的根因是核心语义实现缺口和验证覆盖不足。前次修复恢复了
阿根廷转换，却仍主要使用 E.164 正例和少量国内格式场景验证；不能由测试
数量或“全绿”推断所有常用输入、分机和格式往返已正确。

## 本次复核发现

| 已复现问题 | 原因 | 当前处理 |
| --- | --- | --- |
| BR/AU/NZ/UY 的正常国际拨出号码失败 | IDD 表达式被当作普通字符串；提取器未保留完整模式 | 元数据保留 idd_pattern，按完整表达式识别国际前缀 |
| GB 本国国家码省略 +、国际号带 (0) 失败 | 缺少参考库的受约束规范化 | 仅在候选合法且不破坏合法原值时规范化，增加幂等和独立参考断言 |
| 国内/国际/拨号显示丢分机 | 除 RFC 外未携带 extension，缺少地区标记 | 提取 preferredExtnPrefix；完整保留 GB x、默认 ext. 及其余已发布标记，并解析回同一号码 |
| 无匹配格式时给无效号码添加前缀 | 回退把原 NSN 变成不同数字串 | 保留未分组 NSN；参考库无效号码场景继续断言格式 |
| 非数字 NSN 被长度判断接受 | 公开 PhoneNumber 可构造，但可能性 API 缺少词法校验 | 全部 possibility/candidate 接口拒绝非数字输入 |
| possible 被误当作分配或地区判定 | NANP 结构混入长度判断；七位 UAN 被列作范围豁免 | 分开长度可能性与有效性；支持本地长度及 CA UAN；保留 NANP 结构独立辅助函数 |
| ISDN 子地址可注入 URI 参数 | 公开模型的 isub 中分号被直接输出 | 编码保留分隔符；拒绝不合法 PhoneNumber 字段；统一解析 unreserved 转义 |
| 删掉参考返回记录仍可生成测试 | 没有验证完整输入/输出集合 | 校验条数、身份、唯一性、列结构、轨迹及适配器哈希；加入破坏性检查 |

复核还检查了号码比较、非地理网络、实时格式化、模式边界和元数据生成。
未给未实现的交互式编辑、号码可达性或所有参考库版本的行为作额外承诺。

## 可核查的验证改进

- 原版 Google Java 9.0.17 实际录制 **121 场景**，含 **109 个号码流程**。
  新增国际拨出、国家码规范化、分机、无效和本地长度号码；断言 extension，
  对有效号码验证参考国内格式、参考 RFC 和本库 RFC 的完整往返。
- JS 1.11.20/max 的 **2,299 输入与六条轨迹**保留，并校验派生请求集合。
  元数据/格式差异仍公开记录。CA UAN 的 valid/region/type 范围豁免已删除；
  possible 的 Java/JS 语义冲突单独说明，原版 Java 结果直接断言，不予豁免。
- 两类记录共 **7 项破坏性检查**（删/重复返回、删/截短轨迹）明确失败；两个
  未损坏副本为通过对照。失败必须来自完整性检测，不能由缺文件或工具错误冒充。
- `examples/review` 经公开 API 覆盖验收原缺陷及本轮国际拨号、分机和可能性修复。

```bash
node scripts/acceptance.mjs
node scripts/check-oracle-integrity.mjs
moon run --target js examples/review
```

Windows 无 C 编译器时先用 `--targets js,wasm,wasm-gc`，native 使用 WSL/GCC。
最终逐目标结果、源码指纹和独立安装结果分别见 acceptance-results.json 与
published-consumer-results.json。原 0.9.0 记录归档在 docs/history。
